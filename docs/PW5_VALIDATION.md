# pw.5 移植验证

日期：2026-10-04。上游基线为 `75bc229fbc4266880ce5e57dbb4d924705301650`，贡献分支 `pw5-flight-control`。此版本以 Project Wingman（PW）的鼠标操控手感为优化目标，主要按 F-14D 实机反馈调校，参数可按其他机型和个人需要调整。

## 独立构建

- Windows x64；MSVC 14.41.34120，Windows SDK 10.0.22621.0。
- 在新克隆目录内建立独立 Python 3.13.1 虚拟环境，从官方 PyPI 按固定 SHA-256 安装 Lupa 2.8；通过 Lua 5.4 执行脚本检查。
- 从本分支 `src/` 编译；使用仓库内固定 Lua 5.4.7 和匹配 UE4SS 头文件，无需本地优化工程或相邻 UE4SS 源码目录。
- DLL SHA-256：`36d4e1f246c5deb2aedbe8267fedd27cb556fb1a59d0574c4ecde87548781100`，与原 pw.5 已实测 DLL 完全相同。
- Payload 的 Lua 与 DLL 桥接号均为 35；旧桥接 30–34 被 Lua 拒绝。DLL 文件版本仍为 `0.2.30-pw.5`，不自行指定新的上游正式版本。

## 检查结果

| 检查 | 结果与边界 |
| --- | --- |
| 16 组控制器检查 | 通过；含普通倾斜/倒扣恢复、陡降、近垂直、键位、自由观察、协调转向、预测/制动、斜转、高 G 请求、后方保持、偏航开关及姿态保护 |
| 4 组实际原生函数隔离检查 | 通过；从 `mouse_aim.cpp` 提取实际更新、输入处理、配置读取及状态，检查前后台/暂停、手动轴让权、失效回退、姿态重置与热重载 |
| 1 组部署配置检查 | 默认 INI 与 F-14D 预设通过实际原生读取函数，验证启动/重载、关键响应值和键位；默认值保持 85/1.25/0.10/关闭偏航增强，预设为 89/1.35/0.12/开启 |
| 3 个 Python/Lua 测试 | 部署目录实际 Lua 语法、重映射功能键/前台限制、拒绝旧 DLL 桥接均通过 |
| 全新安装模拟 | 实际 `Install.ps1` 在模拟游戏目录运行成功；DLL/Lua/INI/预设与 Payload 一致，配套运行库及启用项正确 |
| 共存升级模拟 | 自定义 INI 字节不变，共享加载器/设置、其他模组文件及启用列表元数据保留；旧配置和旧 DLL 有备份，部署模块文件与 Payload 一致 |
| 未知运行库模拟 | 安装器拒绝不匹配的 UE4SS，模拟目录中所有已有文件哈希不变 |

控制器回归保留 576 组后方/偏航组合、864 组斜转对照、144 组响应对照及既有水平/陡降等案例。代表性结果与原 pw.5 相同：576 组最终误差最大约 0.28°、倾斜峰值约 85.75°，最坏到位时间差 +0.200 秒；864 组斜转平均到位时间在该合成模型中从冻结 pw.3 的 7.029 秒变为 5.018 秒。

这些是**原发布参数下的合成模型结果**，不是 AC8 实机性能，也不代表 89°个人预设的过冲边界。没有把其他工程的 14 个 P1 探针测试移入此 PR；此分支计数为 **21 组原生 + 3 个 Lua 测试 + 3 种安装模拟**。

## 复跑

按 README 创建虚拟环境并安装开发依赖。在 x64 Developer Shell 中或让构建器通过 vswhere 找到 MSVC 后执行：

```powershell
.\.venv\Scripts\python.exe tools/build_native.py --test-only
.\.venv\Scripts\python.exe tools/build_native.py --update-payload
.\.venv\Scripts\python.exe tools/check_package.py
```

非默认工具链位置可追加 `--vs-dev-cmd 'VsDevCmd.bat 的完整路径'`。Git 位于 PATH 时，`build/BUILD-MANIFEST.json` 还记录当前提交和工作区状态；无 Git 时这些字段为 null，源码/输出哈希仍记录。构建器仅在 `--update-payload` 下写入仓库中的部署 DLL。

安装模拟在 `build/fixtures/` 下创建专用目录并保留供检查，使用占位 EXE 文件，不启动游戏。未知运行库检查只针对运行库兼容性，不把它描述为任意损坏文件的全覆盖检测。

## 实机范围

源版本主要按 F-14D 调校，玩家对当前个人参数反馈顺手；其他机型可以自行调整。本次移植没有覆盖真实游戏文件或重跑实机验收。匹配速度/高度的版本对照、所有机型的稳定性和最大机动性尚未验证。

游戏原生高 G 有触发等待；日志 `highGRequested` 只记录组合键，没有游戏高 G 激活标志或空速，不能据此精确分离游戏等待和输入限制带来的延迟。ONLINE/STORE 行为保持上游状态，未增加菜单或网络阻断。
